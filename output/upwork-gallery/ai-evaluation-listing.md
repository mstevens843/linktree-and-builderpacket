3. SCOPE AND DELIVERY

- One existing text-based workflow through an API or local callable function.
- 25 frozen test cases based on client examples and agreed failure conditions.
- Up to two tool schemas where relevant; tools must use mocks or a client-provided test sandbox.
- Two recorded passes per supplied version.
- Up to two existing versions/configurations: 25 cases x 2 passes x 2 versions = at most 100 case runs.
- With one supplied version: 25 cases x 2 passes = 50 case runs, establishing a baseline and exposing inconsistencies. The reusable runner supports future comparisons.
- Case runs are workflow invocations, not necessarily individual provider/model calls. Usage fees depend on the client's workflow and are paid by the client within an agreed test budget.
- Run time and usage limits are agreed before execution. Unbounded or long-running autonomous agents require different scope.
- Python OR TypeScript runner, selected to fit the environment. One implementation language, not two implementations.
- Explicit deterministic checks where feasible and documented human-review rubrics where semantics cannot be reliably reduced to an automated rule.
- Known-good and known-bad output controls to check the graders.
- Recorded inputs, outputs, settings, and results, with secrets excluded.
- Recorded findings distinguish failed checks, API/errors, incomplete runs, inconsistent answers, and items needing human review. Unscored/error cases do not silently count as passes.
- Findings report with severity, evidence, and recommendations. A finding is not promised if the agreed cases show no defect.
- Version comparison is observational on this small agreed corpus, not a general model ranking or a statistical certification of reliability.
- Source code, cases, a reusable CI-suitable command with documented exit behavior, setup notes, and two revisions to the suite and report.
- New CI pipeline installation, extra runs/versions, product fixes, browser/voice testing, security audits, and ongoing monitoring need separate scope.

FAQ:
1. What kinds of AI applications can you test?
One text-based chatbot or agent workflow exposed through a test API or local function. Checks can cover structured outputs, supported answers, up to 2 tool schemas, and failure handling. Browser-only, voice, and unbounded agents need separate scope.

2. Do I need to provide two versions?
No. With one version, I record 2 passes across the 25 cases to establish a baseline and show inconsistent results. With two supplied versions, I run 2 passes on each and compare the outcomes. The package includes up to 100 case runs.

3. How do you score answers that can vary?
I use deterministic checks where behavior can be specified precisely and documented rubrics for answers requiring human review. A wording change alone is not a failure. Scores apply to the agreed cases, not every possible real-world interaction.

4. Are model costs and CI setup included?
You pay model and hosting fees within an agreed test budget. I provide the runnable suite, exit-code behavior, and CI instructions. Wiring a new CI pipeline, scheduled monitoring, or additional case runs requires separate scope.

5. Will you fix the problems you find?
This package delivers the test suite, findings, and prioritized recommendations. Product fixes are separate. Two revisions cover the agreed cases, scoring, runner, or report; additional workflows, versions, or cases need separate scope.
