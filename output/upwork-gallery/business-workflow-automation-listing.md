FAQ:
1. What counts as one workflow?
One flow between one source and one destination, using one file format or API endpoint per side. Includes one trigger, up to 3 processing steps, and up to 1,000 records per run. Extra workflows or two-way sync need separate scope.

2. Can you connect the tools I already use?
Yes, when they provide suitable documented APIs or CSV/JSON files. This package uses Python or TypeScript. Send the tools and access details before ordering so I can confirm compatibility. Browser-only tools need a separate scope.

3. Where does it run, and are there ongoing costs?
I install it in one ready environment you control, such as an existing server or supported local setup. Scheduled or webhook runs need suitable hosting. You pay hosting and API fees. Ongoing monitoring and maintenance are separate.

4. What happens if an API fails or a run is repeated?
Failures are logged with recovery instructions. I add duplicate checks where supported and retry only safe operations. If an external action's outcome is uncertain, the workflow flags it for review instead of blindly repeating it.

5. What do the two revisions cover?
Adjustments to the agreed mappings, processing rules, and workflow behavior. A new source, destination, trigger, feature, larger volume, or additional workflow changes the scope. You receive the source code and operating instructions.
