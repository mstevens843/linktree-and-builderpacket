## Package scope and acceptance

- One existing browser-buildable React application with source access, adapted with Capacitor for either iOS OR Android, up to five agreed existing screens. Login counts toward the five if included.
- One app and one existing backend. Client supplies a working HTTPS backend, existing business logic, sample data, and an authentication approach compatible with the selected mobile platform.
- Compatibility review before ordering. Frameworks dependent on server-rendered pages, unavailable source exports, desktop-only APIs, or major redesign may require separate work.
- Capacitor project setup, app identity, configuration of supplied app icon assets and splash screen, and platform build/signing configuration.
- Adjustments within the five screens for mobile layout, safe areas, keyboard behavior, scrolling, navigation/back behavior, and foreground/resume states.
- Adapt one existing compatible login/session flow where present, including agreed allowed origins and redirects. No new identity provider, custom OAuth protocol work, native payment system, or backend auth redesign.
- Verify up to three agreed user journeys, loading/error states, and network-loss handling on one physical phone and a second screen size through simulator/emulator. Document device and OS versions; no full compatibility matrix.
- Source code, Xcode or Android Studio project, build instructions, verification notes, and a signed internal test build. iOS: upload to the client's internal TestFlight group. Android: signed test APK and release AAB, with internal track setup if the client's console is ready.
- Two revisions to the agreed mobile adaptation. One platform, five screens and existing functionality remain fixed.
- Store listing creation, public store submission/review, a second platform, new backend features, offline synchronization, push notifications, subscriptions/in-app purchases, custom native plugins, Bluetooth and background processing are separately scoped.
- Client supplies source, branding, working backend, test accounts and required signing/developer-account access. Client pays account, hosting and provider fees. Internet-dependent functionality remains internet-dependent.
- Apple minimum-functionality rules mean a repackaged website alone may not qualify for public distribution. Review fit before purchase; delivery of a test build does not guarantee store approval.
