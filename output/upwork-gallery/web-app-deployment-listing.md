## Package scope and acceptance

- One existing, functional application from one repository, deployed into one environment on either Render or Vercel.
- Up to one frontend and one Node.js or Python backend, where supported by the selected host. A combined application also qualifies. Compatibility is confirmed before ordering.
- Build/start configuration, environment variables, platform Git deployment configuration, and deployment-specific settings such as allowed origins or callback URLs.
- Connection to one existing, reachable database, with the required schema already in place. No new database provisioning, data movement, or schema migration.
- One client-owned domain with up to two application hostnames, such as www and api, DNS configuration and managed HTTPS. No email DNS changes.
- Verification of up to three agreed existing user flows, relevant logs, route refreshes, and frontend/backend connectivity.
- Working public URL, configuration changes, a list of required environment-variable names without secret values, verification notes, and deployment/code-rollback instructions.
- One revision to the agreed deployment configuration and handoff.
- Application must already run and build with supplied instructions. Configuration-related deployment fixes are included; application rewrites, dependency upgrades, new features, and functional bug repairs require separate scope.
- First launch into the chosen environment. Existing live-service migrations, custom CI systems, extra workers/services, database recovery, ongoing monitoring, load testing, and availability guarantees are outside scope.
- Client supplies repository access, a funded hosting account, ready domain/DNS access, required existing services, and test credentials. Client pays hosting, domain and provider charges.
