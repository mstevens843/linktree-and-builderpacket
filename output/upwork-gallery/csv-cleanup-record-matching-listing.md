## Scope and acceptance

- One cleanup-and-matching task for one type of record, such as products, companies, or customer records. Up to two flat CSV files, 10,000 input data rows combined, 20 columns per file, and 20 MB combined. Header rows are excluded from the row count.
- Client supplies exports with one header row and one record per row. This package handles CSV data, not Excel formulas/macros, scans, PDFs, nested JSON, scraping, or database migration.
- Up to five agreed cleanup rules, such as trimming whitespace, normalizing specified labels, standardizing unambiguous dates/numbers, and flagging missing or invalid values. Each rule can apply to agreed columns. Missing facts are not invented.
- One deduplication rule set and one matching configuration using up to three agreed identifying fields. Exact or normalized matches can be linked according to those rules. Optional similarity-based candidate suggestions use one agreed text field.
- Original files remain preserved. IDs and leading zeros are treated as text where required. Unknown date locale, conflicting values, blank match keys, and non-unique identifiers are flagged rather than silently coerced.
- Each input row gets a traceable source file/row reference. Output includes cleaned CSV files, a match/disposition report, and an exceptions list. Any dropped duplicate is accounted for with its retained row and reason.
- Fuzzy similarities are candidate suggestions, not verified identities or probability claims. Ambiguous matches and conflicting duplicate groups stay in a review queue. No fuzzy auto-merging, unsourced enrichment, or promised match rate.
- Check row counts, required columns, missing values, key uniqueness, and agreed exact-match cardinality. Manually spot-check up to 50 records or candidate pairs, in addition to automated file-wide validation.
- Deliver one Python script/configuration for the agreed file schemas, run instructions, and a concise before/after quality summary. The script is a reusable handoff, not an ongoing hosted data pipeline.
- One revision covers corrections or agreed rule adjustments on the same input files. New files, a new record type, extra rules, changed schemas, exhaustive manual adjudication, and ongoing updates require separate scope.
- Client provides representative samples and matching/cleanup decisions, confirms permission to process the data, and supplies only the columns needed for the task. No client data is uploaded to external enrichment or AI services as part of this package.
- Acceptance: all inputs are accounted for, agreed transformations and match rules are reproducible, and the cleaned files, record links, exceptions, script, and summary are delivered. Completeness depends on the supplied data; no guarantee that every record can be matched.
